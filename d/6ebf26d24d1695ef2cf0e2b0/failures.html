실패 처리

연동은 실패를 어떻게 다루느냐로 갈린다

코드원인처리
AUTH_TIMEOUT회원 서버 응답이 400ms를 넘거나 매장 네트워크가 끊김키오스크는 정상가로 즉시 진행(결제를 막지 않음). '회원 확인이 지연되어 정상가로 진행합니다' 안내 + 영수증에 사후정정 코드 인쇄, 서버에 미인증 결제로 기록
DUPLICATE_SUBMIT손님이 [인증]·[결제] 버튼을 연타해 같은 요청이 두 번 도착requestId·idempotencyKey로 기존 결과를 그대로 재응답(duplicated:true). 할인 2회 적용·이중 정산 기록 없음
AUTH_EXPIRED인증 후 메뉴를 고르다 180초 초과(견적도 함께 만료)결제 직전 재검증에서 차단하고 인증 화면으로 복귀. 만료된 authId로 온 commit은 거부
QR_REVOKED분실 신고 후 재발급된 이전 QR을 그대로 스캔인증 거부 + '재발급된 코드로 다시 시도해 주세요' 안내. 휴대폰번호 인증으로 우회 가능, 시도 이력 기록
IMPORT_ROW_INVALID업로드 명단에 번호 자릿수 오류·성명 공백·같은 번호 중복 행배치 전체를 반려하지 않고 정상 행만 스테이징. 반려 행은 원본 행번호와 사유로 반환, 관리자 확정 전까지 운영 명단 미변경
SETTLE_MISMATCH토스 승인 금액과 견적의 회원가가 불일치(견적 만료 후 결제 등)commit 보류 후 관리자 큐로 이관. 결제 자체는 유효하게 두고 할인 적용 여부만 사람이 판정 — 자동 취소·자동 재승인은 하지 않음

⚠ 이 화면의 모든 값은 합성 데이터입니다. 납품물이 아니라 제안용 시안입니다.

키오스크 플러그인과 회원 서버 사이의 요청/응답 계약을 실제 페이로드로 고정하고, 통신 끊김·중복 결제·명단 갱신 실패까지 처리 경로를 그려 둔 연동 설계 데모입니다.

할인은 화면이 아니라 계약에서 어긋납니다. 인증은 됐는데 응답이 늦어 정상가로 결제되거나, 손님이 [인증] 버튼을 두 번 눌러 할인이 두 번 적용되거나, 주 1회 올리는 엑셀 명단에 중복 번호·공백이 섞여 어제 되던 기사님이 오늘 미인증으로 뜨는 식입니다. 그래서 이 데모는 성공 화면이 아니라 타임아웃·중복·명단 오류가 났을 때 키오스크가 무엇을 띄우고 서버가 무엇을 남기는지를 먼저 보여줍니다.

연동 구성

무엇과 무엇이 어떤 순서로 오가는가

1. POST /v1/auth/verifyQR 또는 휴대폰번호로 회원 여부 확인 → 인증세션 발급(유효 180초)
2. POST /v1/auth/verify휴대폰번호 대안 인증(동일 계약·credential 형식만 다름)
3. POST /v1/price/quote장바구니에 인증세션을 붙여 회원가·정상가 확정(결제 전)
4. POST /v1/settlement/commit토스 결제 승인 결과를 인증세션·견적과 묶어 확정 기록(결제 후)

키오스크 플러그인은 매장 단위로 발급한 단말 키로 서명하고, 서버는 등록된 deviceId 목록에 있는 단말의 요청만 받습니다(개인 회원 정보는 단말에 저장하지 않고, 응답도 마스킹된 값만 내려갑니다). 중복 방지는 두 단계입니다 — 인증 요청은 requestId로, 결제 확정은 '단말ID:견적ID' 조합의 idempotencyKey로 묶어, 같은 키가 다시 들어오면 새로 처리하지 않고 최초 결과를 그대로 돌려줍니다(duplicated:true). 재시도는 인증·견적 조회처럼 상태를 바꾸지 않는 호출만 자동으로(최대 2회, 200ms·600ms 간격) 수행하고, 결제 확정은 자동 재시도 대신 관리자 큐에 남겨 사람이 판단하도록 했습니다.

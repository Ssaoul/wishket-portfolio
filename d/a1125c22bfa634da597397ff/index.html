한 질문엔 한 답변만

버튼 하나 띄우고 API만 붙이면 끝나 보이지만, 실제로는 응답이 늦을 때, 실패할 때, 사용자가 전송을 두 번 누를 때 문제가 생깁니다. 질문마다 ID를 붙여 답변이 중복되거나 빠지지 않게 하고, 실패해도 대화 창이 멈추지 않게 설계했습니다.

연동 구성

무엇과 무엇이 어떤 순서로 오가는가

POST /api/chat/sessions
챗봇 창을 처음 열 때 대화 세션 발급 (방문자 단위, 30분 유휴 시 만료)
POST /api/chat/messages
질문 전송 → 서버가 AI API 중계 호출 후 답변 반환. Idempotency-Key 헤더 필수
GET /api/chat/messages/{clientMsgId}
응답 지연·네트워크 끊김 뒤 같은 질문의 처리 상태 조회 (재전송 대신 폴링)
GET /api/chat/sessions/{sessionId}/history
창을 닫았다 다시 열거나 페이지를 이동했을 때 대화 복원

AI API 키는 브라우저에 두지 않고 서버 중계 엔드포인트에만 보관합니다. 프론트는 세션 토큰만 들고 다니고, 허용된 도메인(Origin)과 세션당 분당 호출 수 제한으로 남용을 막습니다. 모든 질문에는 프론트가 만든 clientMsgId를 Idempotency-Key로 붙여서, 연타나 네트워크 재전송이 생겨도 AI는 한 번만 호출되고 답변도 하나만 표시됩니다.

발견 항목

무엇이 병목인지와 그 근거

구조화 데이터(JSON-LD) 미적용 — 국·영문 전 페이지 높음

근거 — 진단 대상 41개 페이지 중 Schema.org JSON-LD 블록이 있는 페이지 0개. Product·Organization·BreadcrumbList 모두 없음. AI 검색·검색 엔진이 제품 정보를 구조화된 형태로 읽어갈 근거가 없는 상태.

조치 — 제품 상세 8개에 Product + Organization, 목록에 BreadcrumbList를 국·영문 각각 삽입. 그누보드 스킨 head 영역에 언어 분기 include 1개를 두고 페이지별 값만 주입하는 구조로 정리.

영문 페이지 hreflang·캐노니컬 미설정 높음

근거 — 영문 12개 페이지 중 hreflang 상호 참조가 걸린 페이지 0개, 캐노니컬이 국문 URL로 잘못 지정된 페이지 5개. 영문 페이지가 국문의 중복 문서로 취급될 여지가 있음.

조치 — ko/en 상호 hreflang + x-default 삽입, 캐노니컬을 자기 URL로 교정. 언어별 URL 규칙을 문서로 고정해 이후 신규 페이지에도 같은 규칙이 자동 적용되게 함.

7차 수정 요청 문서의 미반영 건 산재 높음

근거 — 인계받은 PDF·PPT 7건에서 추출한 요청 41건 중 반영 확인 12건, 미반영 24건, 원문만으로는 판단 불가 5건(요청 문구가 화면 특정 불가). 요청별 접수·완료 기록이 남아 있는 건 0건.

조치 — 41건 전량을 REQ 번호로 원장에 등재하고 상태를 화면에 노출. 판단 불가 5건은 킥오프 미팅에서 담당자 확인 후 확정하며, 임의 해석으로 반영하지 않음.

메타 태그·오픈그래프 누락 및 중복 중간

근거 — 41개 페이지 중 meta description 누락 17개, 동일 description 중복 사용 9개, og:image 누락 23개. 공유 링크에서 대표 이미지가 뜨지 않음.

조치 — 페이지 유형별 메타 템플릿을 만들고 제품·이벤트는 값만 채우는 방식으로 전환. og:image는 기존 배너 원본에서 1200×630 규격으로 파생.

깨진 링크·구제품 상세 잔존 중간

근거 — 내부 링크 점검 218건 중 404 응답 9건, 단종 제품 상세 3개가 목록에서는 빠졌으나 URL 직접 접근 시 노출됨. 그중 2건은 영문 페이지에서만 발생.

조치 — 404 9건은 현행 페이지로 301 연결, 단종 상세 3개는 삭제 대신 노출 정책을 담당자와 정한 뒤 처리. 월 1회 자동 링크 점검을 정기 항목에 포함.

모바일 레이아웃 깨짐 — 제품 상세·이벤트 팝업 중간

근거 — 폭 360px 기준 확인에서 제품 상세 8개 중 4개가 가로 스크롤 발생(고정 폭 표 사용), 이벤트 팝업 1종이 화면 밖으로 잘림. 데스크톱에서는 재현되지 않음.

조치 — 고정 폭 표를 반응형 블록으로 교체하고 팝업 위치 계산을 뷰포트 기준으로 수정. 기존 스킨 CSS를 덮어쓰지 않고 오버라이드 파일로 분리해 되돌릴 수 있게 함.

소스 이력 관리·백업 부재 높음

근거 — 인계 소스에 버전 관리 이력 없음, 동일 기능 파일의 백업본으로 보이는 사본 6개가 같은 디렉터리에 혼재(파일명 말미 _bak, _0311 등). 어느 파일이 실제 동작 중인지 코드만으로 판별 불가한 지점 2곳.

조치 — 인계 시점 전체를 초기 커밋으로 고정한 뒤 작업 단위로 이력 관리. 미사용 사본은 삭제 전 목록화해 담당자 확인을 받고, 실제 동작 파일 판별은 서버 접근 후 확정.

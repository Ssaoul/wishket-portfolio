메일 한 통이 콜 한 건으로

고객사마다 메일 양식이 다르고, 계약이 끝난 장비의 콜도 섞여 들어옵니다. 파싱이 실패하거나 외부 티켓 포털 전송이 끊긴 건을 버리지 않고 격리해, 관리자가 손으로 이어받을 수 있게 만든 화면입니다.

6단계
수신→전송 파이프라인
5종
메일 양식 템플릿
7개
추출 필드
3단계
재시도 후 격리

⚠ 이 화면의 모든 값은 합성 데이터입니다. 납품물이 아니라 제안용 시안입니다.

처리 단계

입력에서 산출물까지 어디를 지나는가

메일 수신
접수 메일함을 폴링해 신규 메일을 원문 그대로 보관한다. 중복 메시지 ID 는 여기서 걸러낸다.
본문 파싱
고객사별 양식 템플릿으로 접수일시·종료일시·장비명·시리얼·담당자·연락처·증상을 추출한다. 매칭되는 템플릿이 없으면 일반 규칙으로 한 번 더 시도한다.
장비 대조
추출한 시리얼을 계약 장비 DB 와 대조해 계약 유효기간·서비스 등급을 확인한다. 미등록·만료는 통과시키지 않는다.
콜 등록
검증을 통과한 건을 서비스콜 레코드로 저장하고 내부 콜번호를 부여한다.
포털 전송
REST API 규격으로 변환해 외부 티켓 포털에 전송하고 반환된 티켓번호를 콜에 붙인다. 실패는 지수 백오프로 3회까지 재시도한다.
상태 회수
전송된 콜의 처리 상태를 주기적으로 조회해 DB 에 반영하고, 종료 건은 이력으로 넘긴다.

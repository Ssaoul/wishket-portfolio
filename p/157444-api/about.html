About

규칙은 그대로, 판단만 자동으로

기존 웹사이트의 수동 배정 화면과 위원 조회 화면은 손대지 않습니다. 어느 위원에게 보낼지를 정하는 판단 부분만 API로 떼어내 붙입니다. 규칙을 코드로 옮기는 일보다, 신청이 한꺼번에 몰릴 때 배정 수를 정확히 세고 한도를 넘기지 않도록 데이터베이스 수준에서 막는 정합성 처리를 이 프로젝트의 실질 난이도로 보고 설계했습니다.

Process

진행 단계

1일차
기존 스키마 파악과 매핑, 배정 규칙 확정 협의(동일 지역 복수 위원 선택 기준·일일 한도·리셋 기준)
2~3일차
위원·인접지역·배정·카운터 테이블 마이그레이션 작성, 시·도 인접 관계 데이터 구축
4~5일차
배정 엔진 구현(동일 지역 → 인접 지역 → 대기)과 동시성 제어, 배정 요청·현황 조회 API
6~7일차
시나리오 테스트와 피크 동시성 테스트, 결과 정리
8일차
기존 환경 배포와 연동 검증, API 명세서·연동 가이드 인계
